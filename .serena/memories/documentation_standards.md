# Documentation Standards

## Report Location Policy
- **All analysis reports** → `Documents/analysis/` folder (EXCLUDED from git)
- **Versioned by date** → Include YYYY-MM-DD in filename
- **Project documentation** → `Documents/architecture/`, `Documents/guides/` (INCLUDED in git)
- **Development artifacts** → `Documents/sessions/`, `Documents/current/` (EXCLUDED from git)

## Git Repository Documentation Policy

### ✅ INCLUDE in Repository (Shared Project Knowledge):
- `Documents/README.md` - Documentation index
- `Documents/architecture/` - System design, database schemas
- `Documents/guides/` - Development workflows, setup guides
- `Documents/assets/` - Diagrams, images for documentation

### ❌ EXCLUDE from Repository (Development Artifacts):
- `Documents/analysis/` - Code analysis reports (personal/team dev use)
- `Documents/sessions/` - Session notes (temporary)
- `Documents/current/` - Work-in-progress documentation  
- `Documents/archive/` - Historical development artifacts
- `Documents/.obsidian/` - Personal note-taking tool configuration

## Analysis Report Naming Conventions
- **Consistent naming**: `ANALYSIS_REPORT_YYYY-MM-DD.md` for ALL analysis reports
- **Local development use only** - Not shared in repository
- Security reports: `SECURITY_REPORT_YYYY-MM-DD.md`
- Performance reports: `PERFORMANCE_REPORT_YYYY-MM-DD.md`  
- Architecture reviews: `ARCHITECTURE_REVIEW_YYYY-MM-DD.md`

## Content Standards
- **Analysis reports are development artifacts** - Not shared in repository
- **Project documentation is shared** - Architecture, guides, setup docs
- **Consistent formatting**: Use standardized template for all analysis reports
- **Consistent naming**: All analysis reports use `ANALYSIS_REPORT_YYYY-MM-DD.md`
- **Emoji indicators**: ✅ Strengths, ❌ Critical, ⚠️ Warning
- **Severity ratings**: Critical/High/Medium/Low with impact descriptions
- **Actionable recommendations**: Specific steps with timeframes
- **Metrics tables**: Quantifiable assessments with percentages
- **Date accuracy**: Use actual generation date (get from system date)
- **Status indicators**: Clear production readiness assessment

## Report Versioning Policy
- Create new dated report for each analysis session
- Keep all historical versions for trend analysis locally
- Reference previous reports in new analyses when relevant
- Use consistent naming scheme: `ANALYSIS_REPORT_YYYY-MM-DD.md`
- Store in `Documents/analysis/` (excluded from git repository)
